# BT26: проверяемое прогнозное размещение

Исследовательская версия0.1.0,21.11.2026. Изолированный подпроект; старые программы и main не изменены.
Все новые входы синтетические. Действующая нейросеть не испытывалась.

Из этого каталога:
```sh
python -m unittest discover -s tests -v
python -m bt26 examples/minimal.json --forecast examples/forecast.json --method P
python -m bt26 examples/minimal.json --method B
python run_study.py --seeds 60 --out results_reproduced
```
Python3.10+; сторонних зависимостей ядра нет. Время — точные рациональные секунды; память — байты; сообщения — биты.

P: (отсортированный вектор команд,время,переназначения,ID), очередь по оптимистической границе.
B: без первого компонента. D: критерийP,нейтральный порядок; на первом допустимом плане не останавливается.
verify.py не вызывает генератор расписания. reconsider — безопасный повторный выбор до запуска, не live migration.

73 теста. Основная серия:60конфигураций,180совпадений с полным перебором назначений при одном построителе.
Среднее число полных проверок6.8 против78. Это НЕ универсальный коэффициент ускорения.
Отрицательный результат сохранён: при синтетическом проигрывании P в среднем медленнееB.
Все входы,планы,CSV и временные трассы генерируются run_study.py. Полный пакет с фактическими результатами и статьёй передан в чат.

FEASIBLE_CERTIFIED относится к данному классу назначений/построителю, не ко всем расписаниям.
FEASIBLE_LIMITED — допустимый план при неполном поиске.
NO_PLAN_IN_CLASS — план не найден в исследованном классе.
SEARCH_LIMIT_NO_PLAN — предел поиска, а не доказательство невозможности.
CLI возвращает0 при найденном плане,2без плана,3при ошибке входа.

Нет настоящей нейросети,переразбиения,банка альтернатив метода1,конечных очередей потока,
живой миграции и службы резервирования физических ресурсов. Не смешивать с результатами НСКФ.
